This plugin connects the Project Management app to MCP and opens up projects, tasks, sprints, milestones and the project wiki to an AI agent through the standard MCP protocol. The agent works with your projects just like a team member does in the interface — honouring project membership, roles and access rights.

32 tools in total, across four right groups: read, tasks, projects and wiki. Each tool name equals its right name, so a token's scope reads directly off the list of tools.

What the agent can do

  Runs tasks

Creates and edits tasks, moves them through the workflow, assigns them, and manages checklists, watchers, tags and the relations between tasks. Adds comments and can edit its own — another author's comment stays off-limits for editing. Every change goes through the app's domain layer, so status transitions, permission checks and notifications are applied automatically. A relation is created two-sided, worded correctly at each end: one task "blocks", the other "depends on".

  Manages projects

Creates projects, changes their settings and workflow, and adds or removes members with the right roles. Editing the member list is limited to project administrators, and the project owner can't be removed by mistake.

  Maintains the wiki

Reads and edits project wiki pages: creates, updates, re-parents them in the tree and restricts access by role. Drafts and access-restricted pages are visible to the agent under the same rules a person sees in the interface.

  Tracks sprints

Reads project sprints and milestones together with their statuses and automation settings, helping to plan and wrap up work. Moving a task in or out of a sprint is done with the same task-update tool.

Tags by name, not by id

The agent puts tags on tasks and takes them off itself, naming them the way a person does in the interface — as a word, with no regard for letter case or internal ids. A name the project does not have is not accepted by default: the plugin answers with the project's own list of tags, so a mistyped word never turns into a new tag. Creating a missing tag is possible, but only when the call explicitly allows it.

Rights and safety

The agent acts not "as the system", but on behalf of a specific contact — the one set as act_as in the token. All checks — project membership, role (admin, manager, member, viewer), wiki permissions — run against that contact. Anonymous access is rejected by every tool.

You grant each token only the tools it needs. Destructive operations (such as deleting a task or removing a project member) require an explicit confirmation, so the agent never does them by accident.

The agent doesn't have to guess

Alongside the tools, the plugin publishes instructions for the agent — four documents it reads on its own, the standard way (MCP resources). They cover what tool descriptions alone cannot say: how moving a task through the workflow differs from an ordinary edit, why a relation between two tasks is a single record each side reads differently, how wiki drafts are treated and which permission is checked where. Without that, an agent works these things out by trial and error — on your real projects.

Available tools

Read — 12. Lists of projects, tasks and comments with filters; project and task cards; statuses and workflow; members, tags, milestones; sprint lists and cards.

Tasks — 12. Create and edit tasks, move them through the workflow, assign an owner, comments (add and edit your own), checklists, watchers, tags, relations between tasks, and deletion (with confirmation).

Projects — 4. Create and configure a project, add and remove members with roles.

Wiki — 4. List and view pages, create and update pages with role-based access control.

Requirements

The plugin requires the MCP app version 1.2.0 or later and the Project Management app version 0.25.0 or later.
